## Locked decisions (do not relitigate; deviations = stop and report)

- **D1 Storage.** Migration 14 adds `settings.ai_api_key_encrypted bytea` and `settings.ai_status text not null default 'unconfigured'` with `check (ai_status in ('unconfigured','ok','auth_failed'))`. Encryption is `api/_lib/crypto.ts` `encrypt`/`decrypt` with the **existing** `CALDAV_ENCRYPTION_KEY` (Outlook-URL precedent — no new Vercel secret). Bytea transport via the existing `bufferToBytea` / `byteaToBuffer`.
- **D2 The browser never sees the key again.** After this chunk the app neither reads nor writes any key column. It reads only `ai_status`. The key leaves the client once, as an HTTPS body to `POST /api/ai/key`.
- **D3 Proxy endpoints** (all wrapped in the existing `calendarRoute` — JWT via `requireUser`, CORS, 500-without-leak; the wrapper's name stays as is):
  - `POST /api/ai/key` body `{ api_key: string }` (zod, min 1, max 512, trimmed). Validates with Anthropic `GET https://api.anthropic.com/v1/models?limit=1` (`x-api-key`, `anthropic-version: 2023-06-01`): 401/403 → **422** `{ ok:false, error:'bad_key' }`, nothing stored; network/5xx → **502** `{ error:'upstream' }`, nothing stored; 2xx → encrypt, write `ai_api_key_encrypted`, `ai_status='ok'`, **and `ai_api_key = null`**; 200 `{ ok:true }`.
  - `DELETE /api/ai/key` → `ai_api_key_encrypted = null`, `ai_api_key = null`, `ai_status='unconfigured'`; 200.
  - `POST /api/ai/triage` body `{ tasks: TriageTask[] (max 300), available_minutes: int 1–1440, timezone: string ≤64 }`, zod-validated against the exact §10 `TriageTask` shape (snake_case). Proxy owns `MODEL`, `MAX_TOKENS = 800`, and `SYSTEM_PROMPT` (moved verbatim from `src/lib/ai.ts`). Returns **200 `{ ok:true, data }`** where `data` is Anthropic's Messages JSON, unmodified — parsing stays client-side (`extractTextBlock` / `parseTriageResult` and their tests are untouched). No key → **412** `{ error:'missing_key' }`. Anthropic 401/403 → set `ai_status='auth_failed'`, **422** `{ error:'bad_key' }`. Anthropic other non-2xx / network → **502** `{ error:'upstream' }`.
- **D4 Model.** `claude-haiku-5-5` (current Haiku per the audit). Lives in the proxy only. Settings' "Uses …" label reads a client constant you keep in sync with the proxy — add a test-free comment pointing at the proxy file.
- **D5 Lazy migration of the legacy plaintext key.** `POST /api/ai/triage`: if `ai_api_key_encrypted` is null **and** legacy `ai_api_key` is non-empty → encrypt it, write `ai_api_key_encrypted`, set `ai_status='ok'`, null `ai_api_key`, then proceed. This spares the operator from re-pasting a key Anthropic's console will not show again. The legacy column is read **only** here, in its own `select` (never added to `CALDAV_COLUMNS`).
- **D6 CSP.** Remove `https://api.anthropic.com` from `connect-src` in `vite.config.ts`. Nothing else in the policy changes.
- **D7 Export/import.** `CREDENTIAL_SETTINGS_KEYS` becomes `['caldav_app_password_encrypted', 'ai_api_key_encrypted', 'outlook_ics_url_encrypted']`. The third is a **pre-existing gap** (found 2026-10-12): today an export carries the Outlook ciphertext and an import writes it back over the live value. `ai_api_key` leaves the list (the app no longer knows it exists). `ai_status` is exported/imported normally.
- **D8 App error mapping** (`src/lib/ai.ts`): `triage()` POSTs to `${VITE_CALDAV_PROXY_URL}/api/ai/triage` with the Supabase JWT, using the same per-request session read as `calendarApi.ts`'s `authHeader` (extract a shared helper only if it is a pure move). 412 → `missing-key`; 422 → `auth`; 401 → `network` with message "Your session expired — sign in again." (JWT, not the AI key); fetch reject / 5xx / 502 → `network`; non-JSON or `ok:false` without a mapped code → `malformed`. `resolveApiKey()` is deleted. `AiErrorKind` and `MESSAGES` copy unchanged except `missing-key` → "Add your Anthropic key in Settings." and `auth` → "Anthropic rejected the key. Replace it in Settings."
- **D9 Settings UI (section 03 "AI assist").** Write-only field. States from `ai_status`: `unconfigured` → empty input + **Save key**; `ok` → "Key saved" (no value, no reveal toggle) + **Replace** (reveals an empty input + Save) + **Remove**; `auth_failed` → "Anthropic rejected the saved key" + Replace + Remove. Save calls `POST /api/ai/key`, Remove calls `DELETE`; after either, refetch settings (never set `ai_status` optimistically — the `caldav_status` rule). Hint copy: "Encrypted and stored server-side; never sent back to this device. Calls go through the calendar proxy." The data-disclosure paragraph stays. Delete the Eye/EyeOff toggle and its imports if now unused. `WhatsNextSheet` copy: "Uses your Anthropic key" stays; the no-key empty state keys off `ai_status !== 'ok'` instead of key presence.
- **D10 Types/cache.** `Settings.aiApiKey` is removed from `db/types.ts`, `mappers.ts` (row type, `settingsFromRow`, `toCachedSettings` strip, patch writer), `sample-data.ts`, `repo.ts` defaults. Add `aiStatus: 'unconfigured' | 'ok' | 'auth_failed'` (cached in Dexie — not a secret). The PRIV-02 strip comment in `mappers.ts` is updated, not deleted.
